# Investigación y fuentes

Proyecto: **vuln-manager**. Plataforma que ingiere SBOM CycloneDX, cruza vulnerabilidades de fuentes públicas y las prioriza con criterios de explotación, exposición y parche, no solo por CVSS.

Fecha de consulta de todas las fuentes: **2026-09-26**. Cuando la fuente era una API se hizo una petición real de verificación y se anota lo que respondió.

## 2. Conclusiones que guían el diseño

1. **La severidad sola no prioriza.** CVSS mide severidad técnica (#27, #28), no riesgo. EPSS mide probabilidad de explotación y FIRST prohíbe multiplicarlo por CVSS (#25, #26). KEV es evidencia de explotación real (#12, #25). La BOD 26-04 (#13) y SSVC (#20) deciden con **árboles o tablas de decisión**, no con puntajes. Por eso la prioridad se calcula con una **tabla de decisión configurable** y cada resultado se explica con la regla que coincidió.
2. **SLA con base normativa vigente.** La BOD 19-02 (15 días para Critical y 30 para High) y la BOD 22-01 fueron **revocadas** el 10-jun-2026 por la BOD 26-04 (#13). El SLA por defecto sigue la Tabla 1 de la BOD 26-04. Los datos de Automatable y Technical Impact salen de CISA Vulnrichment (#15, #16).
3. **Fuentes y límites.**
   - **OSV.dev** (#4–#8) hace el cruce componente → vulnerabilidad por PURL, sin clave y sin límite documentado, y ya incluye la GitHub Advisory Database.
   - **KEV** (#12) se descarga completo con GET condicional.
   - **EPSS** (#23) se consulta en lotes de ≤ 100 CVE (tope de 2 000 caracteres) una vez al día, después de las 13:30 UTC.
   - **CVE Services** (#16) aporta el SSVC.
   - **NVD** (#1, #2) queda como enriquecimiento opcional de CVSS, con un limitador propio de ventana móvil (5 o 50 por 30 s) y 6 s entre peticiones. El limitador estándar de .NET solo controla concurrencia (#40).
4. **VEX con vocabulario oficial.** Los estados son los de CISA (#33) y la importación CycloneDX conserva los valores de `analysis` de la especificación 1.7 (#30). `not_affected` exige justificación o declaración de impacto.
5. **Formato de ingesta.** El MVP acepta CycloneDX JSON de 1.4 a 1.7, validado con la librería oficial (#29–#31). SPDX (#32) queda en el roadmap.
6. **Despliegue gratuito realista.**
   - Render duerme a los 15 min (#51). La sincronización programada se complementa con un cron de GitHub Actions (#54) que despierta el servicio.
   - Render bloquea SMTP (#51), así que las alertas son internas más un webhook HTTPS opcional.
   - 512 MB de RAM (#52) llevan a usar el GC en modo workstation.
   - Neon: 0,5 GB y scale-to-zero (#53).
7. **Seguridad.**
   - Contraseñas con Argon2id según OWASP (#46), porque Identity usa PBKDF2 con 100 000 iteraciones por defecto (#45).
   - Exportación CSV protegida contra inyección de fórmulas (#57).
   - Claves de API por proyecto, contra BOLA (#56 API1).
   - Webhook configurado solo por variable de entorno, contra SSRF (#56 API7).
   - Auditoría sin datos personales y con retención definida (#58).
8. **Dependencias.** Se usa AwesomeAssertions en vez de FluentAssertions 8, que exige licencia comercial (#49, #50). Todas las versiones quedan fijadas según #35, #36 y #48.
